## Player promise
The game is fully playable without any AI agent or fairy assistance. Jan ships as an optional local/offline helper, not a mandatory companion or paid add-on. Players may also use an assistant they already have, independently on their phone, without connecting it to the game. An optional in-game adapter may be developed later where a provider supports an authorized connection. **Provider account costs and APIs are not controlled by this game**; no claim that every provider integrates today.

## Identity versus connectivity
- **Fairy appearance:** a visual embodiment selected or customized by the player, reflecting the assistant's style without pretending an unlicensed likeness or brand is official.
- **Agent adapter:** optional permissioned bridge to a supported external assistant. The fairy remains usable without the bridge.
- **Identity data:** provider choice, chosen appearance, voice preference where supported, explicit permission state, and locally held game preferences. No assumption that provider conversation history transfers.
- **No-agent path:** play normally without assistance. Jan is optional and ships locally for offline help.
- **External phone path:** player says, for example, “Hey Grok, I'm playing TO DOG.” Their existing agent can consult a public, agent-readable GitHub game guide and respond using its own interface, without an in-game connection. Actual ability to fetch GitHub depends on that agent's tools and permissions.
- **Specialties and secrets:** publish general rules plus optional, agent-specific discovery packets. Different assistants may offer distinct specialties, clues and perspectives; no essential progress requires a specific assistant, payment, or undisclosed private file.
- **Fallback:** if external help is unavailable, gameplay continues normally; Jan remains an optional offline helper.
- **Parity:** no paid gameplay advantage for choosing a provider; accessibility, controls, and basic fairy abilities stay available to all.

## Art direction for independent contractors
Produce one small fairy identity study per task, not a whole lore bible. Show clear silhouette, color/pattern/material, movement cue, expression and one recognizable function. Distinguish provider-*inspired* proposals from officially licensed branding. Avoid provider logos, exact protected character likenesses, or implied endorsements without permission. Reuse existing asset framing/provenance conventions when source is supplied; preserve failed concepts for review. No automatic rendering dispatch.

## Engineering direction for independent contractors
First publish a minimal public agent-readable game guide (game identity, mechanics, controls, spoiler boundaries, specialty discovery index, attribution and version). External agents should be able to find it through the public GitHub repository without private credentials. Separately, prototype an optional provider-neutral in-game adapter with a mock agent first. Test: connect/decline/disconnect, permission disclosure, identity swap, loss of service, and built-in fallback. Do not require credentials in the public repository; do not claim Siri/Grok/ChatGPT account connectivity until supported APIs and terms are verified. Separate visual skins from the adapter.

## Review gate
Record CANON / VERIFIED / INFERENCE / PROPOSAL / OPEN; user approval controls promotion. For any public artwork or script, identify creator and original title, source URL, applicable license, and changes. No public contractor gets private command-chain history.
