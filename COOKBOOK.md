## 00 — HOW THE COOKBOOK OPERATES
**Flow:** Request → identify subject → index → recipe → original ingredient/source IDs → current script and scene state → required tools → verify missing items → follow numbered steps → check against sources → catalog result.

**Authority and boundaries**
1. The **owner's latest explicit instruction** controls the requested change.
2. **Existing owner-approved original JPEG / Lattice Master** controls visual identity. [Master JPEG library](https://drive.google.com/drive/folders/1wZLgBCGOoOL-r5bW4xJ95fyCS4F50ULT) and [image index](https://drive.google.com/file/d/1CnpbcZEyggnWBNoFZ43Z_W2SzX11s7ik/view). Images stay in Drive; no art is copied into this GitHub manual.
3. **[ORDERS.md](ORDERS.md)** and its [Drive CURRENT router](https://docs.google.com/document/d/1qHzHhlbDweQQrqcOT8rxuurhSO9SpKmRWs4iqY-CWzc/edit) select production work. Scripts and scene states govern action/dialogue and clip sequencing. They are never replaced by art recipes.
4. **[META.md](META.md)** controls agent handoff. A cookbook recipe is not a render command, scene rewrite or authorization to generate a new concept sheet.
5. **Historical art-direction documents** remain intact on the **ARCHIVE shelf** (below). Their correct source facts are available as ingredients. They do **not** auto-run, outrank owner originals, change live GO, or compete with this cookbook's lookup.
6. Do not infer missing reference images, tool geometry, assembly stock, timing, inventory or links. Mark the *specific* item **MISSING — HOLD AFFECTED NEW SHOT** rather than replacing it.
7. Outputs must match the requested medium. In particular: Meta's *current* assigned output is MP4 video, not HTML, prototype, still, atlas, summary or freshly invented art sheet. No work is triggered merely by editing these files.
8. Approved clips WORLD1-001–100 are DONE/CLOSED, untouched. No rerendering them.
9. All **code and controls** go to GitHub; all **master art/JPEGs** remain in Google Drive. The old source files are not deleted or physically relocated.
10. No copying a generated previous frame into a new master; no invented new styles, models, actors, hardware, or captions.

### RECIPE CARD FORMAT
- **Ingredients**: exact owner reference, current location, source ID, relevant script/state.
- **Utensils**: already approved production/game tools and operations (not a design wish list).
- **Method**: numbered repeatable checks.
- **Serving**: the format actually requested (MP4 / text catalog / code / storyboard / etc.).
- **Do not substitute**: explicit prohibited inventions.
- **QC and provenance**: compare original vs result, record source IDs and any unresolved gap.

### DECISION ALGORITHM
~~~text
WHEN owner asks:
  subject := identify the noun ("fairy", "ship", "Sensei", "book", "chart", "game tool"...)
  recipe := back_index[subject]
  if recipe not found: record "UNINDEXED"; ask/trace original source, DO NOT invent design
  refs := retrieve_exact_owner_masters(recipe)
  live := read_current_orders_only_if_requested_task_is_production()
  context := scene_era + existing_state + approved_tool + requested_output
  if refs missing or context conflicts:
      report missing exact ingredient; HOLD only affected new shot
  else:
      execute ONLY authorized recipe steps using original refs
      validate against master, current orders, and accepted prior results
      catalog output and exact source pointers
END
~~~

## F-01 — FAIRY / STELLAR CUDDLER / CRYSTAL
**Ingredients:** individual owner original, individual character lattice master, current character-role assignment, scene/era, latest approved material correction, any linked score/script.

**Recipe:**
1. Identify *which* fairy and *which version*: don't swap a generic fairy for an approved individual.
2. Load the actual reference pixels, not a prior rendered clip or generated reconstruction.
3. Read the role for *that* scene: BLUE safeguards/shields; RED meters heat/energy; GOLD fits/fastens; SAND issues/counts material; CRYSTAL is the test lead speaking *as the installed part* when established in the current script. Do not force one scene's assignment onto unrelated earlier canon.
4. Keep established singing/music handoff and role chronology where that scene/script requires it.
5. Check exact silhouette, material, wings, hardware, age presentation and accessories against the original and latest scoped owner correction.
6. QC: same approved identity, correctly assigned task, correct scene state, correct source link.

**Preserved source shelf:** [Existing approved concept references](https://docs.google.com/document/d/1_GxSdJ7zLNwHSvgiPUPAyAxfzHq6EYdeIdlqBZVN_p8/edit) · [Drive META.md (MAX canon and Cuddler settings)](https://drive.google.com/file/d/1qXcWXZlaKfRL3dy-GPNYEy365M6DHBIV/view) · [Fairy Lattice source notes](https://docs.google.com/document/d/1hAI_6miFJINH3jjcafc8XbOEz8OBrBj6Gbu4crFv74I/edit). ## G-01 — GAME TOOL LIST / VERBS / SPAWNER
**Ingredients:** approved gameplay canon, [Universal Game Standards](https://github.com/IsekaiSensei/to-world-open-crew/blob/main/GAME_STANDARDS.md), existing Godot actions/scripts when applicable, and exact user-requested game.

**Recipe:**
1. Identify the game and purpose: tool list, mechanics catalog, implementation, or stage/progression.
2. Extract known actions. Historical TO DOG input examples include move, jump, scan, collect/salvage, fuse, fuse box and bolted door; do not mark TO DOG as a live production.
3. Keep the RPSV vocabulary (Rock=Place, Paper=Inspect, Scissors=Develop/Remove, Void=Cancel/Preserve) only where that game's approved system calls for it.
4. Separate **described canon**, **implemented code**, and **idea/not yet implemented**; inspect actual repo files before claiming implementation.
5. Never smuggle a visual design, extra feature or unapproved tool into the list.
6. QC: each row has source, status, owner, input/action, consequence and no invented feature.

## DATA-ONLY 10-SECOND PRODUCTION CELL COMPILER (NOT GO)

- **[Read the tested compiler instructions](scripts/production_cells/README.md)** · [Python compiler](scripts/production_cells/production_cell_compiler.py) · [Input JSON schema](scripts/production_cells/input_schema.json) · [Empty input template](scripts/production_cells/input_template.json) · [Preservation tests](scripts/production_cells/test_compiler.py).
- The compiler creates a **draft** CSV/JSON matrix from an existing approved transcript, without rewriting even punctuation or whitespace, preserving all character turns and source frame IDs. It can include owner-supplied Tale, Fable, Journey, Time-to-Frame and frame-state fields; it cannot originate those values.
- **Two kinds of clocks:** every output container is exactly 10,000 milliseconds; actual spoken delivery has no verified time until owner/audio timecodes are supplied. Draft speech-rate windows must be labeled **ESTIMATED / HOLD**.
- To verify dialogue against the real document rather than against the input JSON alone, provide the actual source UTF-8 transcript and explicit per-turn character offsets; any mismatch is rejected. An external source reference and character identity must have declared provenance; the tool does not independently authenticate the source.
- Unverified metadata holds **only affected** output cells. For overlapping, contradictory, or boundary-crossing timing, retain all words and report the precise gap; **never fabricate a missing word, a silence, a camera move, an object relationship, or an MP4 receipt**.
- This is a **compiler and validation tool only**, not a production order or permission to render. It makes **no changes to current live ORDERS, accepted footage, original JPEGs, or archived files**.
